# PHẦN 1. Hướng đối tượng nâng cao (OOP, Interface & Abstract Class)

Trong các dự án Java Enterprise lớn như Payment Hub, lập trình hướng đối tượng (OOP) là nền tảng cốt lõi giúp hệ thống mở rộng và bảo trì dễ dàng.

---

## 1. Tính Trừu Tượng qua Interface & Abstract Class
Dự án của bạn sử dụng Interface rộng rãi cho lớp Service (ví dụ: `ComponentService` định nghĩa các hành vi, `ComponentServiceImpl` thực thi logic chi tiết).

### Interface (Giao diện)
*   **Định nghĩa:** Chỉ chứa khai báo phương thức (method signature), không chứa code xử lý chi tiết.
*   **Mục đích:** Tạo ra một "hợp đồng" quy định các hành vi bắt buộc. 
*   **Ví dụ:**
    ```java
    public interface ComponentService {
        ProcessingComponent create(ComponentDTO dto, String username);
        void delete(String code, String username);
    }
    ```

### Abstract Class (Lớp trừu tượng)
*   **Định nghĩa:** Lớp cha chung, có thể chứa cả phương thức trừu tượng (chưa có code) và phương thức thông thường (đã có code xử lý chung).
*   **Mục đích:** Chia sẻ lại code dùng chung cho các lớp con.
*   **Ví dụ trong dự án:** `BaseController` chứa các hàm trả về kết quả API chung như `ok()`, `error()`, giúp các Controller con kế thừa lại để tránh lặp code.

---

## 2. Tính Đa Hình (Polymorphism)
Cho phép một đối tượng có thể đóng vai trò ở nhiều kiểu dữ liệu khác nhau.
*   **Ví dụ:** 
    ```java
    ComponentService service = new ComponentServiceImpl(repository, ...);
    ```
    Biến `service` kiểu `ComponentService` (Interface) nhưng thực tế tham chiếu tới đối tượng `ComponentServiceImpl` (Implementation). Điều này giúp bạn dễ dàng thay đổi logic nghiệp vụ mà không làm ảnh hưởng đến các lớp gọi nó (như Controller).
